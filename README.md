# 起始页 · simple_web

一个浏览器起始页（New Tab 替代页）。核心是一行搜索框，下方是天气与日历两张卡片，日历里会填入 LoL 赛事赛程；右上角提供设置抽屉（赛事、天气接口、城市）与主题配色切换。

页面由 `index.html` / `style.css` / `app.js` 三个文件构成，预置数据放在 `data/` 下。**纯静态、无构建步骤、无第三方依赖、无 CDN 外链，也不需要任何本地服务**——双击 `index.html` 即可使用全部功能。

赛程数据来自 Riot 官方赛事接口，该接口带 `Access-Control-Allow-Origin: *`，浏览器可直连，无需代理。

## 快速开始

双击 `index.html` 即可，浏览器以 `file://` 协议加载，所有功能可用（天气与赛程接口均为 HTTPS，且都带 CORS 头）。

如需固定地址，也可用任意静态服务器：

```bash
python -m http.server 8080
```

两种方式功能完全一致，只有地址形式不同；赛程在两种方式下都是直接请求 Riot 接口。

**设为浏览器主页**

在浏览器设置中将主页 / 启动页指向 `index.html` 的路径或上述地址即可。

## 使用说明

### 搜索框

页面主视觉元素。输入内容后按 `Enter` 或点击「搜索」：

- **识别为网址** → 直接在当前标签页跳转（如 `github.com`、`192.168.1.1`、`localhost:3000`）
- **其他内容** → 使用左侧选中的搜索引擎进行检索

快捷键：

| 快捷键 | 行为 |
| --- | --- |
| `/` | 焦点移入搜索框（光标不在输入框时生效） |
| `Ctrl + K` / `⌘ + K` | 同上，并全选已有内容 |
| `Esc` | 关闭浮层；浮层已关闭时让搜索框失焦 |

### 搜索引擎下拉

点击搜索框左侧的引擎胶囊（默认「必应」）展开列表，选项为必应、百度、Google、DuckDuckGo。选中项右侧带对勾标记，选择结果写入 `localStorage`，下次打开自动沿用。

键盘操作：`Enter` / `Space` 展开，`↑` `↓` 移动，`Home` / `End` 跳首尾，`Enter` 确认，`Esc` 关闭并回到按钮。点击页面其他区域同样会关闭。

> 该下拉浮层使用**固定纯白背景**（`#ffffff`）与加重投影，不随明暗主题变化；同时搜索框容器显式抬高 `z-index`，确保浮层始终绘制在下方天气卡片之上，不会被卡片压住或透出卡片内容。

### 设置抽屉

点击右上角齿轮按钮，抽屉从右侧滑出，包含三个区块：

**赛事赛程** — 一个下拉框，列出 Riot 官方接口返回的赛事（已排除云顶之弈等非英雄联盟项目，共 50 个：Worlds、MSI、LPL、LCK、LEC…）：

- 首次打开默认选中列表第一项，之后记住上次选择（存于 `localStorage`）
- 切换赛事会立即重新拉取该赛事的全部对阵，并刷新日历红点与日程
- 下拉框下方显示状态：加载中 / 缓存数据（N 分钟前）· 正在更新… / 已获取 N 场对阵 · 更新于 N 分钟前 / 该赛事暂无对阵 / 更新失败原因
- 断网时保留上次数据并标注缓存时间，不会清空日历
- API Key、语言与排除项在 `data/lol.js` 中配置

**天气接口** — 列出接口（名称 + 地址），同一地址只出现一次：

- 正常只有预置的「默认接口」一条；旧版本遗留的 `{ api }` 配置若与预置地址相同，会自动合并，不再出现「旧版接口」这类重复项
- 点击某一项即切换为该接口，天气立即重新拉取
- 在下方表单填写「接口名称（可留空）」与「接口地址」后提交，即可新增自定义接口并自动启用
- 自定义条目右侧有 `×` 可删除；预置条目不可在界面删除，需修改 `data/weather.js`

**城市** — 只显示当前城市，不再罗列整份城市清单：

- 一行「省份 + 城市」（填了区则追加区名），下方标注「当前城市」；直辖市等省名与市名相同的只显示一次
- 换城市时在下方表单填写并添加；表单分「省份」「城市」「区 / 县」三栏，只有城市必填
- 填了区之后接口按「城市 + 区」查询（如 `广州市天河区`），精度到区，也能避开「天河」「朝阳」这类同名歧义
- 当前城市若是自定义添加的，右侧有 `×` 可删除

抽屉通过关闭按钮、点击遮罩或 `Esc` 关闭；打开期间焦点被限制在抽屉内（`Tab` 循环），关闭后焦点回到齿轮按钮。所有选择即时保存，无需额外确认。

### 主题与颜色

点击右上角的调色板图标打开设置面板：

- **主题颜色**：5 个圆形色块，点击即时生效，同时改变主色、按钮渐变与背景装饰色块
- **深色模式**：开关式切换，标签会在「深色模式 / 浅色模式」之间变化

面板通过点击面板外部或 `Esc` 关闭。当前配色与模式会持久保存。

| 主题色 | 主色值 |
| --- | --- |
| 翠绿（默认） | `#00a76e` |
| 蔚蓝 | `#2f7cf6` |
| 紫罗兰 | `#7c5cff` |
| 琥珀 | `#ef8a3c` |
| 玫红 | `#ec4899` |

### 天气卡片

首次使用为空状态，点击卡片上的「打开设置」或右上角齿轮，在设置抽屉中选择城市（也可在卡片右上角点击城市名直接唤出抽屉）。选定后立即拉取数据。

卡片内容分两部分：

- **上半部分**：天气图标（按天气描述关键词映射为 emoji）、当前温度、天气描述，以及风力、湿度、气压、空气质量等元信息
- **下半部分**：未来几天气温图，由原生 SVG 绘制，无需图表库；有几天的数据就画几列，宽度按卡片实际像素铺满

顶部右侧只保留两个控件：

| 控件 | 作用 |
| --- | --- |
| 城市名（带定位图标） | 显示「省份 城市」（选了区则追加区名），点击打开设置抽屉换城市 |
| 刷新图标 | 强制跳过缓存重新请求 |

图表的每一列结构如下（每列外有淡灰色圆角底板，整列包住）：

```
┌──────────┐
│   周三    │  ← 顶部：只显示周几
│   20°    │  ← 最高温（实线折线 + 圆点）
│   14°    │  ← 最低温（浅色折线 + 圆点）
│   多云    │  ← 底部：天气类型，日夜间不同时写作「多云转晴」
└──────────┘
```

数据默认缓存 15 分钟，刷新页面不会重复请求；缓存与「城市 + 接口」绑定，切换任一项都会重新请求。

### 日历卡片

卡片分上下两部分：**单周日期条** + **当日日程**。

**日期条**只显示当前所在的一周（周日至周六），每格上方是星期、下方是日期数字：

- 今天以主题渐变圆形填充并加投影
- 选中的日期用主题色浅底圆形标记，点击任一天即切换选中
- 跨月周中不属于当前月份的日期会淡显（如 11 月 29、30 日出现在 12 月 1 日所在周）
- 周末（首尾两格）的星期文字使用主题色
- **该日期有日程或比赛时，数字下方显示一个红点**

**日程**区显示选中日期当天的安排，按时间升序排列；没有任何内容时显示「暂无日程」。日程较多时列表在固定高度内滚动，底部带渐隐提示。

日程标题（如「今天 · 10月28日 周三」）右侧带一个主题色圆形角标，显示当天日程总数（比赛 + 手动日程合计）；没有日程时不显示角标。

内容有两个来源，混排在同一条列表里：

| 来源 | 样式 | 内容 |
| --- | --- | --- |
| LoL 赛程（自动） | 红色左边条 | 时间 + 对阵（如 `BLG 1 : 0 KC`）+ 阶段与赛制（如 `瑞士轮 · BO1`） |
| 手动日程（`data/schedule.js`） | 主题色左边条 | 时间 + 标题 + 可选备注，时间留空显示「全天」并排在最前 |

对阵比分仅在比赛已结束且有比分时显示，未开始时为 `A vs B`。

顶部导航：`‹` 上一周、`›` 下一周（选中日期同步平移 7 天，保持同一星期几）、「今天」回到本周并选中今天。日期条支持 `←` `→` 方向键逐日切换。

日程数据在 `data/schedule.js` 中维护，详见[新增日程](#新增日程)。

## 实现说明

### 主题系统

主题通过 `<html>` 上的两个数据属性驱动，所有颜色收敛为 CSS 自定义属性：

```html
<html lang="zh-CN" data-theme="light" data-accent="green">
```

- `data-theme`：`light` / `dark`，控制底色、文字、卡片透明度、阴影强度
- `data-accent`：`green` / `blue` / `purple` / `orange` / `pink`，控制 `--brand` 系列与背景色块 `--a1` `--a2`

暗色模式下额外用组合选择器（如 `html[data-theme="dark"][data-accent="green"]`）提亮品牌色并压暗背景色块，保证深色底上的对比度。切换时仅改属性，样式过渡由 `transition` 承担，无需重新渲染 DOM。

### 本地状态与持久化

所有状态存放在 `localStorage`，共四个键：

| 键名 | 内容 | 说明 |
| --- | --- | --- |
| `startpage.settings.v2` | `{ engine, accent, theme, accentLocked }` | 搜索引擎、主题色、明暗模式、是否锁定主题色 |
| `startpage.weather.config` | `{ apiId, cityId, customApis[], customCities[] }` | 当前选中的接口 / 城市，以及在界面中新增的自定义条目 |
| `startpage.weather.cache` | `{ data, cityId, apiUrl, at }` | 天气数据、来源标识与写入时间戳，`at` 用于判断 15 分钟有效期 |
| `startpage.lol.league` | 赛事 id 字符串 | 上次选中的赛事，如 `98767975604431411`；无值时默认列表第一项 |

读取时逐字段校验（引擎 id、主题色 id 是否在已知列表中，`theme` 是否为 `light`/`dark`，配置中的自定义条目是否具备 `id` 与必要字段），任何非法或损坏的数据都会静默回落到默认值；写入包裹 `try/catch`，在隐私模式或存储被禁用时降级为不持久化，不影响页面使用。

旧版的 `{ api, city }` 两个字符串配置会自动迁移：地址 / 城市与预置一致时直接复用预置条目（不再造「旧版接口」重复项），不一致时才转为自定义条目；重复的自定义条目会在载入时清理并写回。

### 网址识别规则

`looksLikeUrl()` 按以下顺序判断，命中任一即视为网址：

1. 包含空白字符 → 不是网址（排除「hello world」这类搜索词）
2. 匹配 `scheme://` → 是网址
3. 匹配 `localhost[:port]` 或 IPv4 地址 → 是网址
4. 匹配 `host.tld` 形式（允许端口、路径、查询串、锚点）→ 是网址

判定为网址后由 `normalizeUrl()` 补全协议：无协议前缀时统一加 `https://`。搜索词则拼接到当前引擎的 `url` 后并做 `encodeURIComponent` 编码。

### 天气数据流

接口来源、参数、完整返回结构与字段说明见 **[WEATHER_API.md](WEATHER_API.md)**。

```
PRESETS = data/weather.js          （预置接口 / 城市）
weatherCfg = localStorage          （选中项 + 自定义条目）
        ↓ 合并
apiList() / cityList()
        ↓
currentCity() 为空 → 渲染空状态
currentCity() 有值 → 缓存未过期且「城市 id + 接口 url」一致 → 渲染缓存
                   → 否则 fetchWeather() → 成功写缓存并渲染 / 失败渲染错误态 + 重试
```

请求格式为 `{api}?city={城市名}`，自动处理接口已带查询串的情况（改用 `&` 拼接）。传给接口的城市名由 `cityQuery()` 生成，优先级为：

1. 条目的 `query` 字段（显式指定）
2. `city + district`，如「广州市天河区」——精度到区，且能避开同名歧义
3. `city` 去掉末尾行政后缀，如「杭州市」→「杭州」

> 该接口的行政区划解析对区名较敏感：只写「天河」会被识别成「武汉天河国际机场」，「天河区」才落到广州天河区。所以区字段保留「区」字、不做后缀裁剪。

响应需满足 `code === 200` 且存在 `data` 字段，否则视为异常。渲染使用到的字段：

- `data.location`：`province`、`city`、`district`，卡片标题优先用本地配置（选了区才显示区），缺失时回落到这里
- `data.current`：`temperature`、`weather`、`wind`、`wind_level`、`humidity`、`pressure`、`air_quality`
- `data.forecast[]`：`date`、`day_of_week`、`day_weather`、`night_weather`、`high_temp`、`low_temp`，由 `upcomingDays()` 按 `date` 丢掉已经过去的条目（接口首项可能是昨天，不能直接 `slice(1)`），剩余几天就画几列

图表为运行时生成的 SVG（`viewBox` 320×176）：纵向范围由最高温 / 最低温的极值加 20% 留白确定，横向按天数等分；每列先画一块 `--chip-bg` 半透明圆角底板，再叠加周几、两条 `polyline`、数据点、气温数值与天气类型。

默认接口：`https://api.hgovo.cn/API/zgtq`（第三方免费接口，可用性不受本项目控制，可在设置抽屉中替换）。默认返回 5 天预报，卡片就按这个天数绘制；若接口某天少返回一天，图表列数会自动减少，不会留空列。

### 赛程数据流

数据来自 Riot 官方赛事接口 `esports-api.lolesports.com/persisted/gw`，两个请求串行：

```
GET getLeagues?hl=zh-CN
  → leagues[]（51 个）→ 排除 tft_esports 等非 LoL 项目 → 填充下拉框
  → 恢复上次选择，无记录则取第一项
GET getSchedule?hl=zh-CN&leagueId=<id>
  → schedule.events[] → 过滤 type === 'match' → 按本地日期归桶
  → 重绘日期红点与当日日程
```

**为什么不用代理**：该接口返回 `Access-Control-Allow-Origin: *`，且 `Access-Control-Allow-Headers` 放行了 `X-Api-Key`，浏览器预检可以直接通过。实测在 `file://` 页面里发起带 `x-api-key` 的请求返回 200，因此项目不需要任何本地服务。

请求统一走 `lolGet()`：拼 `hl` 参数、带 `x-api-key`、`cache: 'no-store'`、15 秒超时。

用到的字段：

| 字段 | 用途 |
| --- | --- |
| `startTime` | UTC ISO 时间，经 `new Date()` 转本地时区后再取日期与 `HH:MM` |
| `state` | `completed` 时展示比分，`unstarted` / `inProgress` 显示 `A vs B` |
| `blockName` | 赛段名，`hl=zh-CN` 下为中文（如「瑞士轮」「第 1 周」） |
| `match.teams[].code` | 队名代号（BLG / T1 / G2），缺失时用 `name` |
| `match.teams[].result.gameWins` | 局分，仅已结束场次有值 |
| `match.strategy.count` | 赛制局数，拼成 `BO3` / `BO5` |

**只保留英雄联盟赛事**：`getLeagues` 会返回云顶之弈（`tft_esports`），由 `data/lol.js` 的 `exclude` 列表排除，同时用 `/tft|云顶/i` 对名称做一次兜底过滤。

### 赛程缓存

赛程不写入任何文件，只做一层浏览器内存/存储缓存：

```
localStorage（startpage.lol.cache） ← 每次拉取成功后写入
        ↓ 打开页面时
先渲染缓存（若有）→ 立即请求接口 → 用最新数据重绘并回写缓存
```

缓存结构（与接口返回的事件同构，渲染逻辑只有一套）：

```json
{
  "leagues": [{ "id": "98767975604431411", "name": "Worlds" }],
  "schedules": {
    "98767975604431411": { "at": 1793113961287, "events": [ /* 原始事件 */ ] }
  }
}
```

几个实现细节：

- **缓存只为省一次白屏**：每次打开页面都会重新拉取，界面上看到的始终是接口最新返回的数据。
- **上限 3 个赛事**：`trimStore()` 按 `at` 保留最近三个，避免 `localStorage` 无上限增长；写入超配额时降级为只保留当前赛事。
- **失败不清空**：接口异常时保留当前渲染结果，状态行改为「更新失败：…（当前显示 N 分钟前的缓存）」。
- **切换赛事不打架**：请求返回时若用户已切到别的赛事，只写缓存不更新界面。
- **想彻底不留缓存**：控制台执行 `localStorage.removeItem('startpage.lol.cache')` 后刷新，之后每次打开都从接口取。

### 视觉与动效

- **毛玻璃**：卡片与搜索框使用 `backdrop-filter: blur(20px) saturate(1.5)`，配合半透明背景 `rgba(255,255,255,.86)`
- **背景色块**：三个固定定位的 `.bg-blob`，`filter: blur(90px)` 形成柔和渐变光晕，颜色取自 `--a1` `--a2`，为主题色提供「可磨」的底色
- **入场动画**：舞台与组件区分别以 `rise`（上浮淡入）错开 0 / 0.1s 播放；浮层使用 `pop`（缩放淡入）
- **滚动条**：全局隐藏但保留滚动能力
- **减动效**：`prefers-reduced-motion: reduce` 下将动画与过渡时长压至 0.01ms

### 可访问性

- 搜索引擎下拉使用 `aria-haspopup="listbox"` + `role="listbox"` / `role="option"` + `aria-selected`
- 主题面板使用 `role="dialog"`，色块使用 `role="radio"` + `aria-checked`，深色模式开关使用 `role="switch"`
- 设置抽屉使用 `role="dialog" aria-modal="true"`，接口 / 城市列表使用 `role="radiogroup"` + `role="radio"`，并实现 `Tab` 焦点循环与关闭后焦点归还
- 赛事下拉为原生 `<select>`（自带键盘与读屏支持），状态文字使用 `role="status"`
- 日历日期条使用 `role="group"`，每日按钮带 `aria-pressed` 表示选中、`aria-current="date"` 表示今天，有内容的日期在 `aria-label` 末尾追加「，有日程」，并支持 `←` `→` 方向键切换
- 天气区域 `aria-live="polite"`，加载与错误状态可被读屏感知
- 所有交互元素提供 `:focus-visible` 焦点环，且焦点环颜色跟随主题色
- 纯装饰性 SVG 标注 `aria-hidden="true"`

### 响应式与适配

| 断点 | 行为 |
| --- | --- |
| `> 760px` | 双列组件布局，卡片间距 14px |
| `561px – 760px` | 保持双列，收紧间距与内边距 |
| `≤ 560px` | 组件改为单列堆叠；搜索框、按钮、字体尺寸同步缩小 |

页面垂直布局刻意将搜索框中心置于视口约 25% 高度处（`padding-top: max(16px, calc(25vh - 30px))`），为下方卡片留出空间，而非整体垂直居中。

## 自定义与扩展

### 新增搜索引擎

在 `app.js` 的 `ENGINES` 数组中追加一项即可，下拉列表与选中逻辑会自动生效：

```js
const ENGINES = [
  // ...
  { id: 'sogou', name: '搜狗', url: 'https://www.sogou.com/web?query=' },
];
```

### 新增主题色

需两处配合，缺一不可：

1. `style.css` 中新增一组变量块，`data-accent` 值与之一致：

```css
html[data-accent="cyan"] {
  --brand: #0891b2;
  --brand-light: #22b8d8;
  --brand-dark: #0e7490;
  --accent-soft: rgba(8, 145, 178, .12);
  --a1: #a5f3fc;
  --a2: #cffafe;
}
```

2. `app.js` 的 `ACCENTS` 数组中登记同 `id` 的条目，供色块渲染与合法性校验：

```js
{ id: 'cyan', label: '青碧', color: '#0891b2' },
```

若希望深色模式下也有良好表现，可再补一条 `html[data-theme="dark"][data-accent="cyan"] { ... }` 覆盖 `--brand` 与 `--a1` `--a2`。

### 维护天气接口与城市

`data/weather.js` 是预置清单的唯一来源，编辑后刷新页面即生效：

```js
window.WEATHER_DATA = {
  apis: [
    { id: 'hgovo', name: '默认接口', url: 'https://api.hgovo.cn/API/zgtq' },
    { id: 'backup', name: '备用接口', url: 'https://example.com/api/weather' },
  ],
  cities: [
    { id: 'hangzhou', province: '浙江省', city: '杭州市' },
    { id: 'guangzhou-tianhe', province: '广东省', city: '广州市', district: '天河区' },
    { id: 'hongkong', province: '香港特别行政区', city: '香港特别行政区' },
  ],
};
```

- `id` 需唯一，改动会让已保存的选择失效（回落到列表首项），非必要不要改
- `province` 与 `city` 相同（直辖市、特别行政区）时卡片只显示一次
- `district` 可选，填了会按「城市 + 区」查询并显示三段标题；区名要带「区」字，否则可能被解析到同名地点
- 城市条目可加 `query` 字段，显式指定传给接口的名称，优先级高于以上推导

需要临时增删时，也可以直接在设置抽屉里操作，自定义条目存在 `localStorage`，不会写回本文件。

### 更换天气接口

三种方式：

- 设置抽屉中切换已有接口
- 设置抽屉中新增接口地址（即时生效，无需改代码）
- 修改 `data/weather.js` 的 `apis`，作为长期预置项

自定义接口需满足：`GET {api}?city=城市名`，返回 `{ code: 200, data: { location, current, forecast } }`。若字段命名不同，需同步调整 `renderWeather()` 与 `renderForecastChart()` 中的取值。

### 新增日程

编辑 `data/schedule.js`，往 `items` 数组里追加条目即可，刷新页面生效：

```js
window.SCHEDULE_DATA = {
  items: [
    { date: '2026-10-27', time: '09:30', title: '项目周会', note: '会议室 A' },
    { date: '2026-10-27', time: '14:00', title: '需求评审' },
    { date: '2026-10-29', title: '季度复盘' },   // 不写 time 显示「全天」
  ],
};
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `date` | 是 | `YYYY-MM-DD`，与日期条按天匹配 |
| `title` | 是 | 日程标题 |
| `time` | 否 | `HH:MM`，用于升序排列；留空显示「全天」并排在最前 |
| `note` | 否 | 补充说明，显示在标题下方 |

格式不合法的条目（缺 `date` / `title`，或日期不是 `YYYY-MM-DD`）会被自动忽略，不影响其他条目。

### 更换赛事接口 Key / 过滤赛事

`data/lol.js` 集中管理赛事接口配置，改完刷新页面生效：

```js
window.LOL_CONFIG = {
  apiKey: '……',                                  // x-api-key，403 时替换
  base: 'https://esports-api.lolesports.com/persisted/gw',
  hl: 'zh-CN',                                   // 赛段名语言
  exclude: ['tft_esports'],                      // 需要排除的赛事 slug
};
```

- `apiKey` 失效时设置抽屉会显示「赛事列表获取失败：HTTP 403」
- `exclude` 里填 `slug`（如 `tft_esports`），可排除任意赛事；名称里含 `TFT` / `云顶` 的也会被兜底过滤
- `hl` 改成 `en-US` 后赛段名（瑞士轮 / 第 1 周）会变成英文

### 调整缓存时长

修改 `app.js` 中的 `WEATHER_TTL`（毫秒）：

```js
const WEATHER_TTL = 15 * 60 * 1000;  // 改为 30 分钟即 30 * 60 * 1000
```

## 已知限制

- **天气依赖第三方接口**：接口不可用时只能显示错误态，项目本身不内置任何天气数据源
- **赛程依赖公开 Key**：用的是 `lolesports.com` 网页端内置的公开 Key，不是官方发放的开发者凭证；若 Riot 轮换导致 403，需在 `data/lol.js` 中替换
- **赛程接口无官方文档**：返回结构若变更，解析可能失效；赛事时间以接口返回为准（UTC 转本地）
- **无自动定位**：城市需在设置中选择或手动添加，不调用 Geolocation
- **配置仅存本地**：`localStorage` 按浏览器与协议隔离，换浏览器或从 `file://` 切到 `http://` 后需重新设置
- **不落盘**：赛程只在浏览器 `localStorage` 里留一份缓存，不写项目文件；清理浏览器数据后需重新等待接口返回
- **无 PWA / 离线能力**：未注册 Service Worker，离线时页面可打开，天气不可用，赛程退化为上次缓存
- **抽屉内不做校验联调**：新增接口仅校验协议格式，接口是否真的可用需在切换后由天气卡片反馈
- **城市清单较长时需滚动**：抽屉内的列表有最大高度并独立滚动，滚动条按全局约定隐藏

## 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 天气一直显示「正在获取天气…」 | 接口超时或被网络拦截，检查 API 地址是否可达；点击刷新重试 |
| 天气报错「接口返回异常」 | 接口 `code` 不为 200，通常为城市名无法识别，尝试更换标准城市名 |
| 选了区但天气不对 | 区名必须带「区」字（只写「天河」会解析到武汉天河机场），或改用「城市 + 区」的 `query` 字段显式指定 |
| 主题或引擎选择在刷新后丢失 | 浏览器隐私模式或禁用了本地存储，属预期降级行为 |
| 搜索框下拉背景异常 | 下拉固定为纯白 `#ffffff`；若仍异常，检查是否有浏览器扩展注入了样式 |
| 设置抽屉里没有城市 | `data/weather.js` 未正确加载（控制台会给出提示），检查文件是否存在、`<script>` 路径是否正确 |
| 修改 `data/weather.js` 后没有变化 | 浏览器缓存了旧文件，强制刷新（`Ctrl + F5`）；或 `id` 与已保存的选择冲突导致回落到首项 |
| 新增接口后天气报错 | 接口地址不可达或返回结构不符，用浏览器直接访问 `{api}?city=杭州` 验证 |
| 日程显示「暂无日程」 | 该日期在 `data/schedule.js` 中没有条目，或 `date` 不是 `YYYY-MM-DD` 格式被过滤 |
| 赛程下拉只有「暂无赛事」 | 接口 Key 失效（403）或网络不通，检查 `data/lol.js` 中的 `apiKey`，并在浏览器直接访问接口确认 |
| 赛程有数据但日历没有红点 | 该周确实没有比赛；或选中了往期赛事，换一个赛事再看 |
| 赛事列表里少了某个赛事 | 该赛事被 `data/lol.js` 的 `exclude` 排除，或接口本身未返回 |
| 状态行一直显示「缓存数据 · 正在更新…」 | 接口请求慢或失败，数据会保留；刷新页面重试，或检查网络 |
| 想强制重新拉取赛程 | 控制台执行 `localStorage.removeItem('startpage.lol.cache')` 后刷新 |
| 日程条目顺序不对 | 无 `time` 的条目视为「全天」排在最前，其余按 `time` 字符串升序，请确认格式为 `HH:MM` |
| 想彻底重置所有设置 | 打开开发者工具，执行 `localStorage.clear()` 后刷新 |
